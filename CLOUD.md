# Свое облако SHM

В этой ветке есть серверная часть облака SHM: замена `cloud.myshm.ru`, совместимая
с клиентом SHM (`Core::Cloud`) и официальной админкой (`danuk/shm-admin`, раздел «SHM Cloud»).

Облако дает клиентским установкам SHM:

- регистрацию и вход в облачный аккаунт с привязкой к IP сервера;
- баланс и его пополнение через платежные системы облака;
- подписку (открывает промокоды и сводную аналитику);
- каталог модулей платежных систем: бесплатных и платных;
- курсы валют ЦБ РФ с надбавками клиента (конвертер валют, оплата в Telegram Stars).

## Как это устроено

Облако — это обычная установка SHM, у которой включена переменная `SHM_CLOUD_SERVER=1`.
Владельцы других установок SHM становятся ее клиентами, а подписка и покупки модулей
работают через стандартный биллинг SHM: пользователи, баланс, услуги, автопродление.

```
Установка SHM (клиент)                        Облако (SHM + SHM_CLOUD_SERVER=1)
SHM_CLOUD_URL=https://cloud.example.com/shm/v1/cloud
  админка -> /admin/cloud/*  --HTTPS, Basic-->  /shm/v1/cloud/*  (Core::CloudServer)
  spool   -> скачивание модулей             -->  /shm/v1/cloud/service/paysystems/download
```

Код:

| Файл | Назначение |
|---|---|
| `app/lib/Core/CloudServer.pm` | серверная часть облака |
| `app/public_html/shm/v1.cgi` | маршруты `/cloud/*`, включаются `SHM_CLOUD_SERVER=1` |
| `app/lib/Core/Cloud.pm` | клиент: адрес облака берется из `SHM_CLOUD_URL` |
| `app/cloud/paysystems/` | встроенный каталог модулей платежных систем |
| `app/t/api/cloud_server.t`, `app/t/api/cloud_paysystems.t` | тесты |

## Образы

Официальные образы `danuk/shm-core` не знают про `SHM_CLOUD_URL` и `SHM_CLOUD_SERVER`,
поэтому и облако, и клиенты должны работать на образах из этой ветки.
Workflow `.github/workflows/docker-publish.yml` собирает их в GitHub Container Registry при пуше в `cloud`:

```
ghcr.io/<владелец репозитория в нижнем регистре>/shm-core:cloud
ghcr.io/<владелец репозитория в нижнем регистре>/shm-api:cloud
```

В `.env` установки:

```
SHM_REPO="ghcr.io/robertsexx"
CORE_VERSION=cloud
```

Если пакеты в GHCR приватные, на сервере нужен `docker login ghcr.io`, либо сделайте пакеты публичными в настройках GitHub.
Админка и клиентский кабинет (`danuk/shm-admin`, `danuk/shm-client-2`) остаются официальными.

## Запуск облака

1. В `.env` облака добавьте `SHM_CLOUD_SERVER=1` и запустите `docker compose up -d`.
2. Опубликуйте облако по HTTPS на своем домене (прокси перед контейнером `api`).
   Адрес для клиентов: `https://cloud.example.com/shm/v1/cloud`.
3. В админке облака, раздел «Конфигурация»:
   - `billing.captcha_secret` — задайте свою случайную строку. Со значением по умолчанию капчу регистрации можно подделать;
   - `api.url` — внешний адрес облака, из него строятся ссылки на оплату;
   - `pay_systems` — способы оплаты для пополнения баланса в облаке. Модули для них положите в `/app/data/pay_systems`, например из `app/cloud/paysystems`;
   - `cloud_server` — настройки облака (все поля необязательны):

   ```json
   {
       "strict_ip": 1,
       "sub_category": "cloud-sub",
       "ps_category": "cloud-ps",
       "tg_url": "https://t.me/+invite_link",
       "currencies": {
           "url": "https://www.cbr.ru/scripts/XML_daily.asp",
           "extra": { "XTR": { "name": "Telegram Stars", "base": "USD", "ratio": 0.013 } }
       }
   }
   ```

   | Поле | Значение |
   |---|---|
   | `strict_ip` | привязывать аккаунт к IP сервера клиента (по умолчанию `1`) |
   | `sub_category` | категория услуг подписки |
   | `ps_category` | категория услуг платных модулей |
   | `tg_url` | ссылка, которую видят клиенты с активной подпиской |
   | `currencies.url` | источник курсов в формате `XML_daily.asp` ЦБ РФ |
   | `currencies.extra` | дополнительные валюты: `value` — курс в рублях, либо `base` + `ratio` — доля курса другой валюты. По умолчанию добавляется `XTR` = 0.013 USD |

4. Создайте услуги (категория — не длиннее 16 символов):
   - **тарифы подписки**: категория `cloud-sub`, «разрешена к заказу», стоимость и период.
     Поле «следующая услуга» задает тариф продления, например «первый месяц за 100» → «месяц за 300»;
   - **платные модули**: категория `cloud-ps`, «разрешена к заказу», стоимость, период и конфиг
     `{"paysystem": "yookassa"}`. Период — срок действия покупки в месяцах, для бессрочной покупки укажите большой, например `1200`.
     Модули без такой услуги бесплатны.

## Подключение клиентов

В `.env` клиентской установки (на образах из этой ветки):

```
SHM_CLOUD_URL=https://cloud.example.com/shm/v1/cloud
```

После `docker compose up -d` раздел «SHM Cloud» в админке клиента работает с вашим облаком так же,
как с `cloud.myshm.ru`: регистрация с капчей, вход, пополнение баланса, подписка, покупка
и настройка платежных систем, конвертер валют.

При регистрации или первом входе аккаунт привязывается к IP сервера клиента. После переезда
на другой сервер админка предложит «Сбросить IP и войти» — для этого нужен пароль аккаунта.

Тексты в самой админке (ссылка на `@myshm_support_bot`, список преимуществ подписки) зашиты
в образ `danuk/shm-admin` и из облака не меняются.

## Каталог платежных систем

Встроенные модули лежат в `app/cloud/paysystems`. Свои модули и замены встроенных кладите
в `/app/data/cloud/paysystems` (это том, он переживает обновления образа). Модуль — пара файлов:

- `<name>.cgi` — скрипт, который клиент скачивает в `/app/data/pay_systems` и запускает как CGI
  (`https://<клиент>/shm/pay_systems/<name>.cgi`). Только текст в UTF-8;
- `<name>.json` — описание для админки:

```json
{
    "title": "ЮKassa",
    "description": "Короткое описание в списке",
    "version": "1.0.0",
    "infoMessage": "<p>HTML с инструкцией по подключению</p>",
    "fields": [
        { "name": "api_key", "label": "Секретный ключ", "type": "password", "required": true },
        { "name": "mode", "label": "Режим", "type": "select", "default": "a",
          "options": [ { "value": "a", "label": "A" } ],
          "visibleIf": { "field": "enabled", "value": true } }
    ]
}
```

Типы полей: `text`, `password`, `url`, `email`, `number` (`min`, `max`), `checkbox`, `select` и `multiselect` (`options`).
Дополнительно: `default`, `placeholder`, `helpText`, `hidden`, `visibleIf`. Значения сохраняются в конфиг `pay_systems` клиента.
Если поднять `version`, в админке клиентов появится кнопка «Обновить».

Встроенные модули перенесены из открытых скриптов, удаленных из репозитория в коммите `9996847`,
и исправлены:

| Модуль | Что изменено |
|---|---|
| `yookassa` | уведомление перепроверяется запросом к API ЮKassa вместо проверки IP (заголовок `X-Real-IP` подделывается); чеки отключаемые |
| `yoomoney` | защита от повторного зачисления по `operation_id`; тестовое уведомление не создает платеж |
| `freekassa` | второе секретное слово обязательно; пользователь берется из подписанного уникального номера заказа, повтор уведомления не зачисляется |
| `cryptopay` | пользователь из поля `payload` счета, проверка `update_type`, защита от повторов |
| `wallet` | обработка всех событий уведомления, совместимость со старыми именами настроек |

Модуль `cryptocloud` не перенесен: его уведомления не проверялись вообще, а API v1 устарел.
Модули, которые появились в `cloud.myshm.ru` позже, закрыты — их нужно писать самостоятельно.

У всех модулей есть копии (ключи `<name>_1` в `pay_systems` с `"paysystem": "<name>"`): для уведомлений
по копии добавьте к адресу уведомлений `?ps=<ключ копии>`.

## API облака

Пути указаны относительно `SHM_CLOUD_URL`. Методы с Basic-авторизацией проверяют привязку к IP.

| Метод и путь | Авторизация | Назначение |
|---|---|---|
| `GET /test` | нет | проверка доступности |
| `GET /user/captcha` | нет | капча для регистрации |
| `PUT /user` | нет | регистрация (`login`, `password`, `captcha_token`, `captcha_answer`) |
| `GET /auth?login=&password=`, `POST /auth` | нет | вход, привязка к IP. Клиент из этой ветки со своим облаком использует POST, чтобы пароль не попадал в логи |
| `POST /auth/reset` | нет | сброс привязки к IP (`login`, `password`) |
| `GET /user` | Basic | аккаунт и баланс |
| `GET /user/pay/paysystems` | Basic | способы пополнения баланса в облаке |
| `DELETE /user/autopayment?pay_system=` | Basic | отвязать сохраненный способ оплаты |
| `GET /service/sub/get` | Basic | текущая подписка (`status`, `expire`, `next`, `tg_url`) или 404 |
| `GET /service/sub/list` | Basic | тарифы (`service_id`, `name`, `price`, `next`, `price_next`) |
| `POST /service/sub/reg` | Basic | оформить подписку (`service_id`); при нехватке средств 402 `insufficient money` без создания заказа |
| `POST /service/sub/renewal` | Basic | тариф продления (`service_id`, `-1` — не продлевать) |
| `GET /service/paysystems/list` | Basic | каталог модулей (`price`, `paid`, `version`, `fields`) |
| `GET /service/paysystems/order?ps=` | Basic | купить модуль |
| `GET /service/paysystems/download?ps=` | Basic | скачать модуль (403 — не куплен) |
| `GET /service/currencies/list` | Basic | курсы с надбавками клиента |
| `POST /service/currencies/list` | Basic | сохранить надбавки (`currencies`: `{USD: {addition_type, addition_value}}`) |

## Что облако хранит о клиентах

В `settings.cloud` аккаунта: IP привязки, версия SHM клиента и время последнего обращения,
надбавки к курсам валют. Количество пользователей клиента (заголовок `SHM_INFO_CNT`) не сохраняется.
Запросы к API облака, как и любые запросы к SHM, пишутся в журнал `logs_api` (пароли скрываются).

## Проверка

Тесты облака запускаются в окружении разработчика (`contributing/docker-compose.yml`,
в нем облако включено на самой установке):

```
docker compose exec core prove /app/t/api/cloud_server.t /app/t/api/cloud_paysystems.t
```

`cloud_server.t` проходит весь путь: регистрация с капчей, вход, подписка (с откатом неоплаченного
заказа), покупка и скачивание модулей, валюты, привязка к IP, а затем работа клиента `Core::Cloud`
с этим же облаком. `cloud_paysystems.t` отправляет модулям уведомления с верной и неверной подписью
и повторные уведомления.
